THE GIT FIELD GUIDE

Understand how Git tracks your work.

Learn how commits build a project history, how branches let you work safely, and how GitHub helps a team review and share changes. For command syntax, jump to the Git dictionary.

From working files to saved history

Working tree

The files you can see and edit. Use git status to find changes and git diff to read them.

Staging area

The changes you picked for your next snapshot. Use git add to stage a file and git diff --staged to review it.

Repository

Your saved commits and branches. A commit records the staged snapshot with a message, author and parent commit.

A steady local workflow

  1. Check where you are: git status and git branch --show-current.
  2. Read what changed: git diff.
  3. Stage just the related files: git add path/to/file.
  4. Review the staged snapshot: git diff --staged.
  5. Commit one clear idea: git commit -m "Describe the change".
  6. Check again: git status.

Small commits are easier to understand, review and undo. A good commit message says what changed and, where useful, why.

Branches, merges and conflicts

A branch is a movable name for a line of work. Create one for a focused change with git switch -c feature/name. When it is ready, merge it into the branch you want to update:

git switch main
git merge feature/name

If both branches changed the same part of a file, Git pauses and marks the conflict. Read both versions, write the result you want, remove the marker lines, then stage the resolved file and commit. Git cannot infer the intended wording for you.

Merge or rebase?

Merge keeps the shared history

git merge connects two lines of work. When they have diverged, the merge commit records how they came together.

Rebase replays your commits

git rebase main reapplies your branch’s commits on top of a newer base. Rewritten commits get new IDs. Rebase commits that are still yours to change; avoid rewriting commits other people rely on.

For an interactive clean-up, git rebase -i HEAD~3 opens a todo list for the last three commits. You can reorder, edit, combine or drop them. If you are unsure mid-rebase, git rebase --abort returns to the starting point.

Move one change, or put work aside

git cherry-pick <commit> copies one chosen change onto your current branch. It is useful for a small fix you need in another line of work.

git stash push -u -m "short note" puts tracked edits and untracked files aside temporarily. git stash pop reapplies the latest entry. Review the result, because applying a stash can also cause conflicts.

Recovering history carefully

git reflog shows where your local branch and HEAD recently pointed. It can help you find a commit after a reset or rebase. Inspect first, then restore a chosen commit with a command such as git cherry-pick <hash>.

Commands such as git reset --hard discard working-tree changes and move a branch. Practice history rewrites only in the generated, resettable MSIT Git Lab folders. Do not run those steps in a repository with work you need.

Tags and bisect

A tag names an important point in history, often a release. Use an annotated tag for a release note: git tag -a v1.0.0 -m "First release". Inspect it with git show v1.0.0.

git bisect narrows down a regression by asking which commits are good and which are bad. Give it one known-good revision and one known-bad revision, test each point Git selects, then use git bisect reset to leave the search.

From your computer to GitHub

A remote is another copy of your repository, often on GitHub. git remote -v lists it. Push your branch with git push -u origin feature/name. A pull request asks others to review that branch before it is merged.

Review a pull request by reading the changed files, asking questions and checking that the change fits the project. After it is merged, update local main with git switch main and git pull.

A practice loop that sticks

  1. Predict what the next command will change.
  2. Run it in your terminal.
  3. Check with git status, git log --oneline --graph --all or git show.
  4. If you get stuck, read the error and inspect before trying another command.
  5. Reset an MSIT Git Lab exercise and do it again from memory.

Git dictionary

Short definitions for the words and commands you’ll meet throughout the learning path.

Bash/Terminal Basics

Make a new folder (aka make directory)
mkdir <FOLDERNAME>
Navigate into an existing folder (aka change directory)
cd <FOLDERNAME>
List the items in a folder
ls

Configuring Git

Check Git version
git --version
Set your name
git config --global user.name "Your Name"
Set your email
git config --global user.email youremail@example.com
Set your GitHub account (case sensitive)
git config --global user.username uSeRnAmE

Git Basics

Turn Git on for a folder
git init
Check status of changes to a repository
git status
View changes to files
git diff
Add a file’s changes to be committed
git add <FILENAME>
To add all files changes
git add .
To commit (aka save) the changes you’ve added with a short message describing the changes
git commit -m "your commit message"
Copy a repository to your computer
git clone <URL>

Git Branches

Create a new branch
git branch <BRANCHNAME>
Move onto a branch
git checkout <BRANCHNAME>
You can create and switch to a branch in one line
git checkout -b <BRANCHNAME>
List the branches
git branch
Rename a branch you’re currently on
git branch -m <NEWBRANCHNAME>

Git Remotes

Add remote connections
git remote add <REMOTENAME> <URL>
Set a URL to a remote
git remote set-url <REMOTENAME> <URL>
View remote connections
git remote -v

Pulling in Git

Pull in changes
git pull
Pull in changes from a remote branch
git pull <REMOTENAME> <REMOTEBRANCH>
See changes to the remote before you pull in
git fetch --dry-run

Push & Merge in Git

Push changes
git push <REMOTENAME> <BRANCHNAME>
Merge a branch into current branch
git merge <BRANCHNAME>

Deleting Remotes and Branches in Git

Delete a local branch
git branch -D <BRANCHNAME>
Delete a remote branch
git push <REMOTENAME> --delete <BRANCHNAME>

The original command list includes commands such as git branch -D, which can force-delete an unmerged branch. Practice destructive commands only in a disposable repository.

More Git terms

Working tree git status
The files in your project folder, including edits you haven’t saved in a commit yet.
Staging area git add
The changes you’ve selected to include in your next commit.
Commit git commit
A saved snapshot of staged changes, with a message and a link to its parent commit.
Branch git switch -c name
A movable name for a line of work. Create a branch to work on a change separately.
HEAD git log
Git’s reference to the commit or branch you currently have checked out.
Remote git remote -v
A named connection to another copy of your repository, often hosted on GitHub.
Fetch git fetch
Download updates from a remote so you can inspect them before integrating them.
Pull git pull
Fetch remote updates and integrate them into your current branch.
Merge git merge
Join changes from another branch into the branch you’re currently on.
Merge conflict
A place where Git needs you to choose how overlapping changes should fit together.
Rebase git rebase
Replay your commits on a new base. Rebased commits get new IDs.
Clone git clone
Create a local copy of a repository, including its commit history.
