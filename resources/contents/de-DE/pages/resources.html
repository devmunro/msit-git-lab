DER GIT-LEITFADEN

Versteh, wie Git deine Arbeit festhält.

Hier lernst du, wie Commits die Projekthistorie aufbauen, wie Branches sicheres Arbeiten ermöglichen und wie ihr Änderungen über GitHub teilt und besprecht. Befehle zum Nachschlagen findest du im Git-Wörterbuch.

Zum Git-Wörterbuch ↓

Von deinen Dateien zur Projekthistorie

Arbeitsverzeichnis

Hier liegen die Dateien, die du sehen und bearbeiten kannst. Mit git status findest du Änderungen und mit git diff liest du sie nach.

Staging-Bereich

Hier sammelst du Änderungen für den nächsten Stand. Mit git add legst du eine Datei dazu. git diff --staged zeigt dir, was im Commit landet.

Repository

Hier liegen deine gespeicherten Commits und Branches. Ein Commit hält den gestagten Stand samt Nachricht, Autor und Vorgänger fest.

Ein verlässlicher Ablauf

  1. Prüfe, wo du bist: git status und git branch --show-current.
  2. Lies die Änderungen: git diff.
  3. Stage nur zusammengehörige Dateien: git add pfad/zur/datei.
  4. Prüfe den vorgemerkten Stand: git diff --staged.
  5. Committe eine klare Änderung: git commit -m "Änderung kurz beschreiben".
  6. Prüfe danach noch einmal: git status.

Kleine Commits lassen sich leichter verstehen, reviewen und rückgängig machen. Eine gute Commit-Nachricht beschreibt, was sich geändert hat und bei Bedarf auch warum.

Branches, Merges und Konflikte

Ein Branch ist ein beweglicher Name für einen Arbeitszweig. Lege für eine konkrete Änderung einen an: git switch -c feature/name. Wenn sie fertig ist, merge sie in den Branch, den du aktualisieren möchtest:

git switch main
git merge feature/name

Haben beide Branches denselben Teil einer Datei geändert, hält Git an und markiert den Konflikt. Lies beide Versionen, schreib den gewünschten Text und entferne die Markierungszeilen. Danach stage die gelöste Datei und committe sie. Was gemeint ist, kann Git nicht für dich entscheiden.

Merge oder Rebase?

Ein Merge zeigt den gemeinsamen Verlauf

git merge verbindet zwei Arbeitszweige. Sind sie auseinander gelaufen, hält der Merge-Commit fest, wie sie zusammenkamen. So bleibt dieser Punkt der Zusammenarbeit in der Historie sichtbar.

Ein Rebase spielt Commits neu ab

git rebase main wendet die Commits deines Branches auf einer neueren Basis erneut an. Das ergibt oft eine gerade Historie, aber die Commits bekommen neue IDs. Rebase Commits, die noch dir gehören; ändere keine Commits um, auf die andere schon bauen.

Mit git rebase -i HEAD~3 öffnest du eine To-do-Liste für die letzten drei Commits. Du kannst sie sortieren, bearbeiten, zusammenfassen oder entfernen. Wenn du mittendrin nicht weiterweißt, bringt dich git rebase --abort zum Ausgangspunkt zurück.

Einzelne Änderungen übernehmen oder Arbeit parken

git cherry-pick <commit> kopiert eine ausgewählte Änderung auf deinen aktuellen Branch. Das ist praktisch, wenn ein kleiner Fix auch in einen anderen Arbeitszweig soll. Prüfe vorher mit git status und git branch --show-current, auf welchem Branch du bist.

git stash push -u -m "kurze Notiz" legt getrackte Änderungen und neue Dateien vorübergehend beiseite. Mit git stash pop holst du den letzten Eintrag zurück. Prüfe das Ergebnis, denn beim Anwenden kann auch ein Konflikt entstehen.

Historie vorsichtig wiederherstellen

git reflog zeigt, wohin dein lokaler Branch und HEAD zuletzt gezeigt haben. Damit findest du vielleicht einen Commit nach einem Reset oder Rebase wieder. Schau zuerst nach und stelle einen passenden Commit dann zum Beispiel mit git cherry-pick <Hash> wieder her.

Befehle wie git reset --hard verwerfen Änderungen im Arbeitsverzeichnis und verschieben einen Branch. Übe das Umschreiben der Historie in MSIT Git Lab nur in den eigens angelegten Lab-Ordnern, die du jederzeit zurücksetzen kannst. Führe solche Schritte nicht in einem Repository mit wichtigen Änderungen aus.

Tags und bisect

Ein Tag benennt einen wichtigen Punkt der Historie, oft ein Release. Für ein Release kannst du einen annotierten Tag mit Nachricht anlegen: git tag -a v1.0.0 -m "Erstes Release". Mit git show v1.0.0 kannst du ihn prüfen.

git bisect grenzt eine Regression ein, indem du Git sagst, welche Commits gut und welche fehlerhaft sind. Nenn einen bekannten guten und einen bekannten fehlerhaften Stand, teste die Zwischenstände und beende die Suche mit git bisect reset.

Vom Rechner zu GitHub

Ein Remote ist eine weitere Kopie deines Repositories, zum Beispiel auf GitHub. Mit git remote -v siehst du die Verbindung. Push deinen Branch mit git push -u origin feature/name. Ein Pull Request schlägt anderen den Branch zur Prüfung und Diskussion vor, bevor er gemergt wird.

Im Review liest du die geänderten Dateien, stellst Fragen und prüfst, ob die Änderung zum Projekt passt. Nach dem Merge aktualisierst du deinen lokalen main-Branch mit git switch main und git pull.

So bleibt das Üben hängen

  1. Überleg zuerst, was der nächste Befehl ändern wird.
  2. Führe ihn in deinem Terminal aus.
  3. Prüfe das Ergebnis mit git status, git log --oneline --graph --all oder git show.
  4. Wenn du hängenbleibst, lies die Fehlermeldung und schau erst nach, bevor du den nächsten Befehl probierst.
  5. Setz ein MSIT-Git-Lab zurück und wiederhole die Übung aus dem Kopf.

Git-Wörterbuch

Kurze Erklärungen zu den Begriffen und Befehlen aus deinem Lernpfad.

Bash/Terminal Grundlagen

Einen neuen Ordner erstellen (auch bekannt als make directory)
mkdir <FOLDERNAME>
In einen bestehenden Ordner navigieren (auch bekannt als change directory)
cd <FOLDERNAME>
Die Elemente in einem Ordner auflisten
ls

Git konfigurieren

Git-Version überprüfen
git --version
Deinen Namen setzen
git config --global user.name "Dein Name"
Deine E-Mail setzen
git config --global user.email deineemail@beispiel.com
Dein GitHub-Konto setzen (case sensitive)
git config --global user.username uSeRnAmE

Git Grundlagen

Git für einen Ordner aktivieren
git init
Status von Änderungen an einem Repository überprüfen
git status
Änderungen an Dateien anzeigen
git diff
Änderungen einer Datei zum Committen hinzufügen
git add <FILENAME>
Um alle Dateiänderungen hinzuzufügen
git add .
Um die hinzugefügten Änderungen zu committen (auch bekannt als speichern) mit einer kurzen Nachricht, die die Änderungen beschreibt
git commit -m "deine commit nachricht"
Ein Repository auf deinen Computer kopieren
git clone <URL>

Git-Branches

Einen neuen Branch erstellen
git branch <BRANCHNAME>
Auf einen Branch wechseln
git checkout <BRANCHNAME>
Du kannst einen Branch erstellen und in einer Zeile zu ihm wechseln
git checkout -b <BRANCHNAME>
Die Branches auflisten
git branch
Einen Branch umbenennen, auf dem du dich gerade befindest
git branch -m <NEWBRANCHNAME>

Git-Remotes

Remote-Verbindungen hinzufügen
git remote add <REMOTENAME> <URL>
Eine URL zu einem Remote setzen
git remote set-url <REMOTENAME> <URL>
Remote-Verbindungen anzeigen
git remote -v

Änderungen in Git pullen

Änderungen einholen
git pull
Änderungen von einem Remote-Branch einholen
git pull <REMOTENAME> <REMOTEBRANCH>
Änderungen am Remote sehen, bevor du sie einholst
git fetch --dry-run

Push & Merge in Git

Änderungen pushen
git push <REMOTENAME> <BRANCHNAME>
Einen Branch in den aktuellen Branch mergen
git merge <BRANCHNAME>

Remotes und Branches in Git löschen

Einen lokalen Branch löschen
git branch -D <BRANCHNAME>
Einen Remote-Branch löschen
git push <REMOTENAME> --delete <BRANCHNAME>

git branch -D kann auch einen noch nicht gemergten Branch löschen. Übe solche Befehle nur in einem Wegwerf-Repository.

Weitere Git-Begriffe

Arbeitsverzeichnis git status
Der Projektordner mit allen Dateien, auch mit Änderungen, die noch in keinem Commit gespeichert sind.
Staging-Bereich git add
Hier landen die Änderungen, die du für deinen nächsten Commit ausgewählt hast.
Commit git commit
Ein gespeicherter Stand der vorgemerkten Änderungen, mit Nachricht und Verweis auf den vorherigen Commit.
Branch git switch -c name
Ein beweglicher Name für einen Arbeitszweig. Mit einem neuen Branch kannst du Änderungen getrennt bearbeiten.
HEAD git log
Git-Verweis auf den Commit oder Branch, den du gerade ausgecheckt hast.
Remote git remote -v
Eine benannte Verbindung zu einer anderen Kopie deines Repositories, oft auf GitHub.
Fetch git fetch
Lädt Updates vom Remote herunter, damit du sie vor dem Einbinden prüfen kannst.
Pull git pull
Holt Remote-Updates ab und integriert sie in deinen aktuellen Branch.
Merge git merge
Fügt Änderungen aus einem anderen Branch in deinen aktuellen Branch ein.
Merge-Konflikt
Eine Stelle, an der Git deine Hilfe braucht, um überlappende Änderungen zusammenzuführen.
Rebase git rebase
Spielt deine Commits auf einer neuen Basis erneut ab. Dabei bekommen sie neue IDs.
Klonen git clone
Erstellt eine lokale Kopie eines Repositories samt Commit-Verlauf.
